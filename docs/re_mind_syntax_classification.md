# Re:Mind 構文仕様の分類案

仕様書 [remind_specification.md](../remind_specification.md) をもとに、実装順に合わせて Re:Mind の構文を次の3セットに分類する。

## 1. 最小セット（MVP）

まずは「1つの小さなプログラムを通せる」レベルに絞る構成。

- 基本宣言
  - 変数宣言・代入
  - 定数宣言
  - 基本型（int, string, bool）
- 基本文法
  - コメント
  - リテラル
  - 四則演算・論理演算
  - `=` による代入
- 関数
  - 関数呼び出し
  - 値を返す関数
  - `return` / `返す`
- 制御構文
  - `if` 相当の分岐
  - `while` 相当の繰り返し
  - ブロック終了の構文（`ここまで`）
- 実行文
  - `□` で始まる文の実行形式

このセットだけでも、コンソール出力系の簡単なプログラムをトランスコンパイルできる土台となる。

## 2. 中間セット

最小セットを超えて、実用的な構文を追加する段階。

- 配列
  - 配列宣言
  - 配列初期化
- 制御構文の拡張
  - `switch` 相当
  - `for` 相当
  - `do-while` 相当
  - `break` / `continue` 相当の制御
- クラス
  - クラス宣言
  - インスタンス生成
  - フィールド参照
  - メソッド呼び出し
- 例外
  - `try/catch`
  - `finally`
  - `throw`
- コメント・注釈
  - Javadoc 風コメント
  - 引数・戻り値の英字名指定

この段階では、AST とコード生成の構造をかなり本格化させる必要がある。

## 3. 拡張セット

ターゲット言語との親和性を高め、言語仕様としての完成度を上げるための構文。

- 外部ライブラリ連携
  - `using` 相当
  - `import` 相当
  - 既存クラス・メソッドの宣言橋渡し
- 高度な型・オブジェクト機能
  - 継承
  - アクセス修飾子
  - null 条件演算子
  - null 合体演算子
- ターゲット言語依存の柔軟な記述
  - 既存言語構文のそのまま受け入れ
  - 仕様上のパススルー
- 追加の表記ゆれ
  - 省略形
  - 同義表現
  - エイリアス系構文

これは「言語仕様としては豊か」だが、実装コストはかなり高くなる。

## おすすめの実装順

1. 最小セット
2. 中間セット
3. 拡張セット

この順にすると、AST・パーサ・コード生成器の各層を段階的に育てやすい。
