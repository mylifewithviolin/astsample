# 起動パラメータで変換元と変換先を特定できるようにする計画

## 1. 目的

`Program.cs` の起動引数で Re:Mind の変換元ファイルと変換先ファイルを指定し、変換先ファイルの拡張子から C# / Java / VB.NET のコード生成器を選択できるようにする。

現在の `Program.cs` は次の状態である。

- 第1引数の存在を検証しているが、実際の入力には使わず、`variable` / `bubblesort` / `helloworld` からサンプル名を選んでいる。
- `sourceFiles` 配下の固定ファイルを読み込んでいる。
- 第2引数の拡張子を取得しているが、生成器の選択には使っていない。
- C# の `CSharpCodeGenerator` を常に使用している。
- 生成結果を固定の `transcompiledFiles/{caseName}.generated.cs_` に保存している。
- Java / VB.NET の生成器は存在するが、`Program.cs` から選択されていない。

この計画では、Lexer 以降の既存パイプラインを維持し、入力選択・ターゲット選択・出力保存を `Program.cs` の責務として整理する。

## 2. 起動仕様

### 2.1 コマンド形式

```text
dotnet run -- <変換元ファイル> <変換先ファイル>
```

例:

```text
dotnet run -- sourceFiles\helloworldcs.aoi transcompiledFiles\helloworld.cs_
dotnet run -- sourceFiles\variablecs.aoi transcompiledFiles\variable.cs_
dotnet run -- sourceFiles\bubblesortcs.aoi transcompiledFiles\bubblesort.cs_
dotnet run -- sourceFiles\ifthenelsecs.remind transcompiledFiles\ifthenelse.java
```

第1引数は既存のサンプル名ではなく、読み込むファイルのパスとして扱う。相対パスはカレントディレクトリを基準に解決し、絶対パスも受け付ける。

第2引数は生成結果を書き込むファイルのパスとして扱う。既存の `transcompiledFiles` 配下に限定せず、指定された任意の出力パスを受け付ける。

### 2.2 変換先拡張子とターゲット言語

| 拡張子 | ターゲット言語 | 使用する生成器 |
|---|---|---|
| `.cs_` | C# | `CSharpCodeGenerator` |
| `.java` | Java | `JavaCodeGenerator` |
| `.vb` | VB.NET | `VbNetCodeGenerator` |

拡張子の比較は大文字小文字を区別しない。`Path.GetExtension` で取得した値から先頭のドットを除去して判定する。

`.cs_` は本プロジェクトで使用している C# の変換結果ファイル名規約である。

本プロジェクトでは、現時点の運用として C# の変換後ファイル拡張子を `.cs_` のまま維持する。変換結果をプロジェクト内の `transcompiledFiles` フォルダへ出力しているため、通常の `.cs` として保存すると SDK スタイルプロジェクトのコンパイル対象に含まれ、生成されたエントリポイントとトランスコンパイラ本体のエントリポイントが重複する可能性がある。`.cs_` は変換結果を確認・検証するためのファイルであり、通常のC#ソースとして自動コンパイルされないようにするための意図的な拡張子である。このため、今回の実装では通常の `.cs` をC#の出力先として追加対応せず、`.cs_` のみをC#出力として受け付ける。

入力ファイルの拡張子はターゲット言語の判定には使用しない。現在のサンプルにある `.aoi` と、例にある `.remind` のどちらも入力ファイルとして読み込めるよう、まずは拡張子による入力拒否を行わない方針とする。必要になった時点で `.aoi` / `.remind` の入力拡張子検証を追加する。

## 3. 対象ファイルと責務

### 3.1 `Program.cs`

次の責務を `Main` 内または小さな private メソッドへ整理する。

1. 引数個数を検証する。
2. 第1引数から入力ファイルパスを取得する。
3. 入力ファイルの存在を確認し、UTF-8 で読み込む。
4. 第2引数から出力ファイルパスを取得する。
5. 出力ファイルの拡張子を取得する。
6. 拡張子をターゲット言語へ変換する。
7. ターゲット言語に対応するコード生成器を生成する。
8. 入力を既存の Lexer → Parser → SemanticResolver → IRBuilder の順に処理する。
9. 選択した生成器でコードを生成する。
10. 出力先ディレクトリを必要に応じて作成し、指定された第2引数のパスへ書き込む。
11. 生成結果を標準出力へ表示するかどうかを既存の運用と照らして決定する。

現在の次の処理は削除または置き換える。

- `caseName` の判定。
- `sourceFiles/{caseName}cs.aoi` の組み立て。
- `ReMindSourceCode` を通常入力の代替にする処理。
- 固定された `transcompiledFiles/{caseName}.generated.cs_` への保存。
- 常に `CSharpCodeGenerator` を生成する処理。

`const string ReMindSourceCode` は、ファイル入力が失敗した場合の暗黙の代替入力にはせず、仕様上必要な互換用サンプル入力として残すか、不要であれば別タスクで整理する。今回の計画では、指定された入力ファイルを正しく処理することを優先し、ファイルがない場合に空文字列や別サンプルへフォールバックしない。

### 3.2 ターゲット選択処理

拡張子から生成器を選択する処理を、`switch` 式などの単純な一箇所の分岐にまとめる。

概念例:

```text
.cs_       -> CSharpCodeGenerator
.java      -> JavaCodeGenerator
.vb        -> VbNetCodeGenerator
その他     -> E00004
```

既存の `TargetLang` 定数を使う場合は、文字列定数と実際の拡張子判定が一致するように整理する。ターゲット選択の戻り値は、将来の生成器追加を妨げないよう、可能なら共通インターフェースまたは既存の共通 API に寄せる。

### 3.3 `Messages.cs`

既存メッセージを利用し、必要な場合だけ不足メッセージを追加する。

- 引数個数不正: `E00001`
- 入力ファイル不存在: `E00002`
- 入力ファイル読み込み失敗: `E00003`
- 出力拡張子不正、または未対応ターゲット: `E00004`
- 出力ファイルに拡張子がない: `E00008`

出力ディレクトリ作成や出力ファイル書き込みに失敗した場合のメッセージが不足していれば、入力読み込みエラーと区別できる新しいエラーコードを追加する。エラーメッセージには対象パスと例外メッセージを含める。

## 4. 実装フェーズ

### Phase 1: 引数契約を確定する

- 引数は正確に2個とする。
- 第1引数を入力パス、第2引数を出力パスとして扱う。
- 相対パスと絶対パスの両方を受け付ける。
- 入力ファイルの拡張子ではターゲットを決めない。
- 出力ファイルには対応する拡張子が必要であることを決める。

完了条件:

- `sourceFiles` の固定サンプル選択が起動引数の処理に残っていない。
- 引数例をこの文書と `Program.cs` の実装で一致させられる。

### Phase 2: 入力ファイルを直接読み込む

- 第1引数のパスを `File.Exists` で検証する。
- UTF-8 でファイルを読み込む。
- 読み込んだ文字列を Lexer に渡す。
- ファイル不存在時に別サンプルや `ReMindSourceCode` へフォールバックしない。

完了条件:

- `helloworldcs.aoi`、`variablecs.aoi`、`bubblesortcs.aoi` をそれぞれ指定して、指定したファイルの内容が解析対象になる。
- ファイル名中の `variable` や `bubblesort` に依存しない。

### Phase 3: 出力拡張子から生成器を選択する

- `Path.GetExtension` を使って第2引数の拡張子を取得する。
- `.cs_`、`.java`、`.vb` の対応を実装する。
- 大文字小文字を区別しない。
- 拡張子なしは `E00008`、未対応拡張子は `E00004` とする。
- 選択後も Lexer → Parser → SemanticResolver → IRBuilder の共通処理を一度だけ実行する。

完了条件:

- C# 指定時に `CSharpCodeGenerator` が呼ばれる。
- Java 指定時に `JavaCodeGenerator` が呼ばれる。
- VB.NET 指定時に `VbNetCodeGenerator` が呼ばれる。
- 対応外拡張子でコード生成処理へ進まない。

### Phase 4: 指定された出力先へ保存する

- 第2引数の親ディレクトリが存在しない場合は作成する。
- 生成結果を第2引数そのものへ UTF-8 で書き込む。
- 既存の固定出力パスへの書き込みを削除する。
- 出力ファイルの書き込み例外を捕捉し、入力読み込みエラーと区別して表示する。
- 標準出力への表示を残す場合は、ファイル出力と二重になることを計画・仕様に明記する。
- C# の出力先は `.cs_` とし、プロジェクト内の変換結果が通常のC#コンパイル対象へ入らない状態を維持する。

完了条件:

- `transcompiledFiles\任意の名前.cs_` のような出力先を指定できる。
- 出力先の親ディレクトリが存在しない場合でも、作成可能な範囲で正常終了する。
- 指定先以外にケース名由来のファイルを自動生成しない。

### Phase 5: 検証と既存処理の整理

- 既存の `CompareGeneratedOutput` を残す場合は、固定された期待ファイルではなく、必要な検証用ファイルを明示的に扱う設計へ変更する。
- 通常の変換処理では、入力パスと出力パスの指定だけで完了することを優先する。
- `Program.cs` の不要になった `projectRoot`、`caseName`、固定期待ファイル、固定検証ファイルへの依存を整理する。
- C# だけでなく Java / VB.NET の生成器が `ProgramIR` を完全に生成できるか確認する。生成器側の未実装が判明した場合は、起動パラメータ対応とは別の実装タスクとして切り分ける。

## 5. エラー処理方針

| 条件 | 対応 |
|---|---|
| 引数が2個でない | `Messages.E00001` を表示して終了 |
| 第1引数の入力ファイルがない | `Messages.E00002` とパスを表示して終了 |
| 入力ファイルを読めない | `Messages.E00003` と例外内容を表示して終了 |
| 第2引数に拡張子がない | `Messages.E00008` を表示して終了 |
| 第2引数の拡張子が未対応 | `Messages.E00004` を表示して終了 |
| 出力ディレクトリを作れない | 出力用エラーを表示して終了 |
| 出力ファイルへ書き込めない | 出力用エラーを表示して終了 |

エラー終了時は、解析・意味解析・コード生成・ファイル書き込みを途中まで実行した状態で不完全なファイルを残さないようにする。必要であれば一時ファイルへ書き込んでから置換する方式を後続改善として検討する。

## 6. 検証手順

### 6.1 ビルド

```text
dotnet build astsample.csproj
```

### 6.2 C# 変換

```text
dotnet run -- sourceFiles\helloworldcs.aoi transcompiledFiles\helloworld.generated.cs_
dotnet run -- sourceFiles\variablecs.aoi transcompiledFiles\variable.generated.cs_
dotnet run -- sourceFiles\bubblesortcs.aoi transcompiledFiles\bubblesort.generated.cs_
```

確認項目:

- 指定した入力ファイルが読み込まれている。
- C# の生成器が使用される。
- 第2引数のファイルが作成される。
- 出力ファイルの拡張子が `.cs_` であり、生成結果がエントリポイント多重定義を起こす通常の `.cs` ファイルとして扱われない。
- 固定の `caseName` による別名ファイルが作成されない。

### 6.3 Java / VB.NET 変換

```text
dotnet run -- sourceFiles\helloworldcs.aoi transcompiledFiles\helloworld.java
dotnet run -- sourceFiles\helloworldcs.aoi transcompiledFiles\helloworld.vb
```

確認項目:

- `.java` で Java 生成器、`.vb` で VB.NET 生成器が選ばれる。
- 出力内容が各言語の構文として生成される。
- 生成器側の未実装が原因で空出力になる場合は、入口処理の不具合と混同せず別課題として記録する。

### 6.4 エラーケース

```text
dotnet run -- sourceFiles\notfound.aoi transcompiledFiles\out.cs_
dotnet run -- sourceFiles\helloworldcs.aoi transcompiledFiles\out

dotnet run -- sourceFiles\helloworldcs.aoi transcompiledFiles\out.py
```

確認項目:

- 入力ファイル不存在、拡張子なし、未対応拡張子がそれぞれ適切なメッセージになる。
- 引数を1個または3個にした場合に `E00001` になる。
- エラー時に不完全な出力ファイルを残さない。

## 7. 完了条件

- 第1引数で指定した任意の Re:Mind ソースファイルを読み込める。
- 第2引数で指定した任意の出力ファイルへ生成結果を書き込める。
- 出力拡張子 `.cs_`、`.java`、`.vb` からターゲット言語と生成器を選択できる。
- C# / Java / VB.NET の各生成器を共通の Lexer → Parser → AST → SemanticResolver → IR → CodeGenerator パイプラインへ接続できる。
- 既存の固定サンプル名・固定出力先に依存しない。
- 正常系、ファイル不存在、拡張子不正、書き込み失敗の検証手順が実行できる。
- `Program.cs` の実装変更後に `dotnet build astsample.csproj` が成功する。
